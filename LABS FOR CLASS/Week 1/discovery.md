## 5. Goals
The system should be able to prevent double booking
The system should help staff not manually check everything everytime
The system should make people who take equipment fully aware when to return it
## 6. Scope
The system seems to have no control over its own booking system as it doesnt update itself based off bookings
The system doesn't have any dynamic support as its all manual
The system doesn't seem to assign dates properly for returns
The system is unsupportive of those who do take equipment out

## 7. Candidate Requirements
The system will prevent double booking
The system will prevent incorrect dates and give reminders
The system will be automatically changed when equipment is noted 
The system will always be tracking whats avalible and what is not

Performance should stay fast even with automatic features
The system cant have too much authority or might break other aspects
## 8. Requirement Surgery
R1: The system should be easy to use

This is weak because the word easy doesn't specify if its for the staff or user or both. This could imply also many things.
Is it easy in a UI sense? or a low navigation way, or just automatic two buttons, there is too many options

The system should be easy for staff to use to control booking and equipment logs while also providing a fast and efficent but fair booking system to the student

R2: The system should be secure.

Secure in what sense? from outside attackers, or staff manipulating and cheating the system itself or maybe a student just logging in without a password. Does it mean that secure also mean that something cant be undone due to safety, it can be alot.

The system should provide security from unauthorised attackers using login methods while also allowing staff to manipulate anything to do with bookings and nothing beyond, this would protect against internal and external attacks while not getting rid of usability
